# 城市共配 / Urban Flow — v0.9.4

面向「AI＋物流 / 城市配送智能配载」赛题的可运行原型。项目作者：柯浩涵（Kyle），GitHub：[@websafarikyle-hue](https://github.com/websafarikyle-hue)。业务设定为杭州中心仓向方太门店次日配送，订单、箱件规格、运力与费用均为**模拟假设**。门店位置与普通驾车路线基于公开资料，尚未接入企业内部系统或真实业务数据。

## 场景、方案与应用价值

目标用户为城市配送调度员、仓库装载员和逐站交付人员。多门店、多 SKU、时限和异质车队的决策相互影响，分开安排车辆、路线与货物容易出现车厢装得下却无法按配送顺序取出的冲突。工作台将订单模拟与导入、运力选择、路线规划、3D 装载、逐站卸货与可打印执行单连接为一条流程。先最大化按时完成的订单数，再按用户选择优化总工时或配送费用；可切换车辆上限、费用与卸货规则，比较同一数据下的方案和未安排订单。

## 技术实现与验证

浏览器 Worker 中的 JavaScript 求解器使用多起点插入、局部路线调整和候选路线池组合。每个候选均检查时间窗、班次、载重、箱件尺寸、单箱完整支撑及累计顶部承重、车厢碰撞、后门取货可达性、搬移次数和逐站恢复。排程累计装货、行驶、等待、卸货和末端行程；费用由车辆固定费、里程费及人工工时费组成。独立回放校验输出，路线、装箱和卸货界面共享同一结果。35 秒组合比较预算与 45 秒页面保护保留最近校验通过的可行方案。

150 箱、30 单、最多 3 辆车的模拟压力场景，单机独立测时由约 27.51 秒、16 单改善至约 14.63 秒、18 单。逐车容量必要条件将服务量上界收紧为 21 单，剩余最多 3 单改进空间；18 单尚无全局最优证明，费用和工时也无最优性证明。32 项 Python 测试、45 个场景回归、真实 Chrome 桌面/手机与 Worker 退化测试已执行，GitHub Actions 三组审计通过。测试条件和限制详见上述记录。

架构为静态网页、Worker 和共享求解器；`frontend/v03/` 是源目录，根目录的同名文件供 GitHub Pages 使用，`standalone-demo.html` 嵌入相同逻辑。公开门店目录、道路缓存、模拟车队和 SKU 假设见 `data/`、`docs/` 与页面说明。普通驾车时间不包含货车限行、实时拥堵、车辆轴载与装卸现场空间。企业落地需接入真实订单、车辆和资费，在符合保密规则的环境部署，核验司机与仓库操作，完善权限、数据治理和并发扩容。

杭州方太门店次日补货的派车、道路路线、三维装载与逐站装卸工作台。公开门店和模拟业务参数分别标注，大模型助手暂缓。

**[直接打开配送工作台](https://websafarikyle-hue.github.io/urban-loading-planner/)**。电脑和手机浏览器均可访问，无需登录ChatGPT。计算在浏览器Worker中完成。

v0.9.4增加计算时间预算、校验过的进度方案保留、服务量上界与未安排原因分类。150箱场景单独运行约27.5秒降至14.6秒，服务量由16单提高到18单。[性能与服务量诊断](docs/performance-service-2026-10-12.md)。

v0.9.3 修复有限搬移搜索预算导致服务量下降、特殊订单号缓存冲突、真实浏览器添加箱型失败、场景导入及过期执行单问题；增强结果校验与自动回归。[审计与修复记录](docs/audit-2026-10-12.md)。

v0.9.2 合并了最新算法修复，并同步网页与单文件Demo。完整的45个场景由GitHub Actions分三组运行。[发布验证](docs/v092-validation.md)。

v0.9.1 调整了按钮间距和手机布局，使用说明单独显示操作指南。方案分析增加四种方案的时间、费用构成图，可切换对照方案的差异解读、交互车辆时间轴，以及装载率和收货余量。总工时与整批结束时刻分别展示；服务订单集合一致时才显示节省百分比。详细验证见 [v0.9.1 检查记录](docs/v091-validation.md)。

1. 点击模拟次日订单，在20家公开门店中生成12～16家门店的订单；也可下载CSV模板，填写门店编号、时间窗、箱型及数量后导入。
2. 核对订单及车辆，设置最多出车数、三种终点、两种卸货规则、时间或费用目标。全部费用和作业系数可调。
3. 确认生成配送计划，查看先去哪家、到达与卸货完成时刻、道路里程、末段行程和费用。
4. 在装载页旋转车厢，逐箱装车、逐站卸货，查看每步的层、位置、原因及时间估计。完成本段后前往下一站。
5. 比较输入顺序、最近门店、最早截止三规则与联合优化。下载可打印执行单，在浏览器打开后打印或保存PDF。
6. 本浏览器保存最近5个场景；导出JSON后可换设备导入重算。修改条件后，旧结果保留到下次确认。

页面内置“使用说明”。另有常规补货、配件堆叠和有限搬移三个验证样例。

## v0.9功能与模型

五种模拟箱型为烟机、灶具、洗碗机、烟管配件、安装辅料。最多两层，上层由一个下层箱完整支撑，检查累计承重、空间重叠及取货通道。易碎或不可堆叠箱不承托其他货物。搬移假设现场有临时放置空间，未建模绑扎、轴荷、制动或人员转向空间。

小、中、大车型默认固定费160/220/300元每次，里程费1.2/1.6/2.1元每公里，人工费30/35/40元每小时。各值均可修改，全部属于模拟假设。费用＝逐车固定费＋里程费＋完整作业人工费。

时间单位统一为min。总作业时间是所有车辆装车、行驶、等待、卸货和终点行程之和；整批任务历时另显示。当前时间目标优化前者。卸货时长包括准备、逐箱、易碎、重货及临时搬出恢复，按0.5 min向上取整，并计入卸货完成时间窗及人工费。

服务量优先，然后优化所选目标。共享引擎采用多起点贪心插入、2-opt、跨车移单、整线换车、合单修复及可行路线池组合。每条候选联合检查装载、卸货及排程，独立验证器逐步重放操作并复核指标。直接卸货优化最多2200次候选检查；有限搬移额外预留500次检查，另行缓存并保留所有车辆上限的三种参考方案。参考方案检查次数单独显示；路线组合按每个车数分桶保留，总计约1024个状态，浏览器联合计算预算35秒；45秒保护保留最近校验通过的可行方案。参考近期EJOR联合优化论文，未完整复现精确算法或证明全局最优；见[研究依据](docs/research.md)。

20家门店名称地址来自方太官网，坐标取门店或所在商场、楼宇的公开地图参考点，GCJ02近似转WGS84。[逐条来源](data/hangzhou-fotile-store-catalog.json)保留定位类型、查询日期及不确定性。营业和卸货入口未实地核验，模拟订单不代表真实传化客户。

道路为免费OSRM/OpenStreetMap普通驾车估计，本版不把拥堵或货车限行纳入优化。已有54段路径缓存覆盖默认方案及验证样例，自定义方案可在线补查。路径必须与坐标及计划分段时间匹配；更新提示确认重算，缺少匹配数据时显示虚线示意。网络失败保留已有缓存或明确标为估算。免费公共服务无可用性保证。

输入限30单、150箱、6辆车，单仓单日、一次出车、一单同车完成。CSV导入失败保持原场景；导出的执行单绑定本次已确认方案。

## 本地运行与发布

打开standalone-demo.html即可使用内置算法、门店及道路缓存；手机文件预览器可能禁用JavaScript，请用系统浏览器打开。

Python 3.10+执行 `python server.py --open`，或Windows双击start-demo.cmd。网页不需要Node；可选/api/v03/solve接口需Node.js 18+。内部目录保留兼容命名，页面版本为v0.9.4。

```sh
python scripts/build_standalone.py
python scripts/prepare_github_pages.py
```

仓库为公开且 Pages 可用时，可访问 [在线 Demo](https://websafarikyle-hue.github.io/urban-loading-planner/)；私有仓库以仓库内的单文件 Demo 和本地服务为准。若启用 Pages，更新后检查仓库 Actions 的构建部署结果。
