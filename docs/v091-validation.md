# v0.9.1 布局和方案分析检查记录

## 本次修改

- 道路操作与车辆切换分别分组，增加行距、按钮间距和手机端自适应布局。
- 使用说明标签隐藏计划设置、场景保存、算法详情和草案提示，直接进入操作指南。算法详情放在方案分析页。
- 比较四种方案的装车、行驶、等待、卸货时间，以及固定费、里程费和人工费。图表使用统一刻度。
- 切换输入顺序、最近门店或最早截止作为对照，显示实际服务数量、工时、费用和整批历时差异。
- 车辆时间轴支持点击作业段，也支持下拉选择，显示车辆、门店、开始结束时刻与时长。
- 展示每辆车的体积与重量利用率、上层箱数，以及最紧收货截止余量。

所有展示值由已确认方案计算；本次没有修改优化算法。节省百分比仅在服务订单集合相同时展示。车辆并行作业时，总工时与整批历时具有不同含义。

## 验证结果

- Python unittest：32 项通过。
- 两个前端的 JavaScript 语法检查通过。
- 旧版 UI 和当前 UI 自动检查通过，包含确认计算、草案变更、导入和装卸回放。
- 分析模块检查通过：时间与费用合计、装载量、时间窗余量、连续车辆时间轴、服务订单集合不同和零分母情形。
- 实际 Chrome 浏览器：默认方案完成 16/16 单，生成三种基准方案；时间与费用图各四条，时间轴可点击切换。
- 320、390、768、1024、1366px 尺寸检查：页面没有横向溢出，检查到的按钮与输入控件没有重叠。
- 说明页设置、保存、算法区均不可见；道路按钮与车辆按钮间隔至少 16px。
- 三维画布、有限搬移六步回放、下一站和单文件版本仍正常。

浏览器尺寸模拟通过；实体手机触控仍需用户试用反馈。道路时间为普通驾车估计，订单、包装和费用继续明确标注模拟假设。

## 默认方案的实际取舍

同一批 16 单，与最近门店规则相比，联合优化使用 2 辆车，对照使用 3 辆。总工时由约 775.5 min 减至 518.1 min，费用由约 1843.6 元减至 1673.6 元；整批任务历时由约 270.1 min 增至 311.4 min。分析页同时展示这些变化，并解释车辆并行安排对最后结束时刻的影响。
