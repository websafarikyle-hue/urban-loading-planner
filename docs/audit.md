当前 Demo 已形成“订单 → 分车与路线 → 箱件实际坐标 → 逐站卸货”的计算闭环，足以用于功能讨论。原讨论 PRD 中的真实地图道路数据、大模型和论文方法实现尚未完成。仓库 docs/PRD.md 曾将这些要求记为“首版调整”，本次将它们重新列为原需求的差距，等待用户对齐，不能按已完成处理。

## 本次已修复

1. **非法输入返回 500**：orders=[null] 等错误结构会触发 AttributeError。现在按对象、数组、非空 ID/name、来源、有限数值和当日时间校验；该请求返回 400。补充班次结束检查。
2. **布局校验与原始箱件脱节**：此前改变摆放尺寸、重量、易碎标记或订单归属仍可能通过。现在核对原始属性、允许旋转、所属订单和站序，并拒绝非有限坐标。
3. **数据与已显示方案不同步**：编辑器现在先保留草案；确认后以输入快照计算，成功时一起替换数据与方案。计算失败保留原数据、原方案和待确认草案，计算期间拒绝编辑和重复求解。
4. **旧变更草案仍可操作**：无效的新指令清掉旧助手草案；成功导入或重置清掉旧草案，新增单检查 30 单/150 箱上限和箱件 ID 冲突。
5. **时间口径不透明**：新增 service_end，前端展示到达、卸货开始、卸货结束。保持原实现“due 约束开始卸货”并明确标识，是否改成完成交付仍待对齐。
6. **导入省略 start 导致助手数据错误**：新增单使用与后端一致的默认 08:00。
7. **较差结果的展示**：完成订单数少于基础规则时给出提示；成本/里程增加不会呈现绿色改善标记。

## 关键反例：需要对齐业务目标

构造两张订单、同坐标、宽松时间窗与两辆车，剔除道路和时间因素：

- 小单：50×50×50 cm、10 kg，截止 10:00。
- 大单：150×50×50 cm、20 kg，截止 15:00。
- V01：可装大单，载重 20 kg，固定费用 1 元。
- V02：只能装小单，载重 10 kg，固定费用 100 元。

基础规则先处理输入顺序中的大单，再给小单 V02，完成 **2/2** 单。当前联合启发式先处理较早截止的小单，选择便宜的 V01，大单随后无法分配，完成 **1/2** 单。relocate 只接受降成本的移动，因此不能主动把小单移到较贵的 V02 以释放 V01，也不会重新插入未分配的大单。

该问题还未修改，因为需要明确服务与成本的优先级。建议默认“最大化按时完成订单数 → 在服务相同的方案中降低成本”；引入多起点方案、未分配单重试、允许暂时增成本的修复移动，并以基础方案作为已知可行参照。即便采用该规则，启发式仍无全局最优或最大服务数证明。

可复现命令：`python tests/audit_scenarios.py outputs/audit-scenarios.json`。完整反例输入与结果在 audit-results.json 的 counterexample 字段。

## 验证结果与限制

- 原有 15 项测试通过；新增缺陷回归在修复前复现了 500、非法字段未拒绝、箱件属性脱节、缺 service_end；修复后共 **19 项 Python 测试通过**。
- JavaScript 语法检查通过。前端 Node DOM 桩连接真实 API，验证草案取消/确认、失败时不生效、多字段同时提交、计算期间拒绝修改、无效指令、导入后清草案及默认发车时间。
- 10 组固定随机种子模拟场景（每组 10 单/40 箱/3 车）优化方案都完成 10/10。基础规则其中两组为 9/10，其余 10/10；不可将不同服务数的成本差当作同服务量降本率。
- 1 组 30 单/120 箱/9 车可用的场景，两方案均完成 30/30；优化耗时本机约 1.1 秒。该案例不是“30 点、3 车”的能力证明，不是规模上限实验。
- 上述 11 个常规场景用车数、体积利用率均未改善。零搬开是硬约束，不是比较收益。固定原样例仍为 3 车、35% 体积利用率，1089.94 → 1079.82 元（模拟）。
- supported() 和 extraction_blockers() 被装载器与复核函数共同使用；当前复核不等于独立算法实现的证明。几何分离另有测试，需要继续补独立约束验证。
- 浏览器入口再次超时，真实 Canvas 视觉、拖动/缩放、响应式布局和键盘可用性仍未验收。

## 建议先对齐的三项

1. **调度目标**：是否接受默认“尽量全部按时送完，服务相同再降成本”？订单重要性差异后续用 priority 明确。
2. **时间窗口径**：建议“14:00 前送达”以完成卸货为截止；当前实现按开始卸货判定。需定统一口径后一起调整数据、算法、助手与验收。
3. **v0.2 重点**：建议先修服务优先级，再接真实杭州道路矩阵并建立论文模型/小规模精确对照；随后补装车步骤、箱件详情和路线变化高亮，最后接大模型。保留现有页面技术，避免同时迁移全部框架。

本次没有更改目标优先级、时间窗业务语义、升级求解器或接入外部数据服务，便于基于明确差距讨论下一版。
