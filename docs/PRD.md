# Demo PRD v0.3 · 已实现版本

调度员前一天汇总次日杭州方太门店补货任务，先保证交付服务，再按总作业时间或配送费用生成派车、路线和可执行装卸方案。业务关系和参数为模拟。

| 需求 | 实现 / 验收 |
|---|---|
| 20家同品牌地点 | 方太官方名称地址+公开地图参考点及转换说明，含1家社区服务店 |
| 模拟按钮 | 固定种子，随机12～16家各1单；未选门店不参与 |
| 订单草案 | 门店下拉、时间窗、箱件数量/尺寸/重量/规则、增删单；确认计算 |
| 车辆 | 默认6辆池，编辑可用状态/车型/费用，从全池选择最多指定车数 |
| 3种终点 | 回仓、末站结束、指定停车点，正确计入最后行程 |
| 2种卸货 | 无搬移；有限搬移每站0～5件，搬出/恢复实际校验 |
| 2种目标 | 服务量优先，再按总作业时间或费用；剩余订单解释 |
| 费用 | 默认200元/次、1.5元/km、30元/h；统一应用、恢复、逐车编辑 |
| 路线解释 | 站序、逐段距离、到达/等待/卸货、终点、免费道路缓存/路径 |
| 三维装载 | 实际位置、站点着色、旋转缩放、下拉查看箱件详情 |
| 装卸指导 | 逐箱装车、逐站卸货，先搬上层/前方阻挡箱，再卸本站、恢复 |
| 作业时间 | 装车准备+逐箱；卸货准备+逐箱+易碎+重货+搬移，半分钟向上取整 |
| 方案对比 | 同输入基础规则与优化；不同条件历史，仅同订单车辆可比较 |
| 手机 | HTML/CSS/JS、Worker本地计算，不依赖用户电脑持续开机 |
| 保存 | 浏览器5份、JSON导入导出；失败不覆盖有效输入/方案 |

时间窗截止检查卸货完成，含搬移耗时；结束不得超班次。易碎/不可叠箱不得支撑上层；最多两层单箱完整支撑，取货不得造成悬空。超搬移上限则候选拒绝。

总作业时间是各车任务时间之和，与最晚车辆结束时间分别展示。末站结束不含后续调拨；停车点模式含前往指定点。费用和装卸系数为未实测的可调整假设。

算法实现有限启发式，无全局最优保证；失败不证明数学不可行。LLM按用户要求暂缓。真实企业数据、货车限行、卸货入口、完整力学约束与现场标定留待后续。32项Python、11组新引擎、两版前端逻辑及14场景通过；完整手机外观/触控未实机验收。GitHub同步仍需正确项目仓库地址。
